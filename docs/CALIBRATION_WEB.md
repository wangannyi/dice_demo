# 手眼标定 Web 工具

独立服务运行在 K3，现场操作员通过局域网浏览器完成标定。仅支持当前 NERO 七轴、固定 RealSense 相机、末端 ChArUco 板的 eye-to-hand 流程。算法与配置仍以 [原标定流程](CALIBRATION.md) 为准，`calibrate.sh` 的行为不变。

## 启动与停止

在需要应用结果的 **dice_demo 仓库根目录**执行。默认端口为 8091，不与摇骰子网页的 8080 端口共用。

```bash
# 首次设置工程师 PIN；交互输入，不写入命令历史。
bash calibrate_web.sh --set-pin

bash scripts/calibration_web_service.sh start
bash scripts/calibration_web_service.sh status
bash scripts/calibration_web_service.sh stop
```

浏览器访问 `http://<K3地址>:8091`。前台调试可运行 `bash calibrate_web.sh --host 0.0.0.0 --port 8091`；仅预览界面可加 `--readonly`，不会连接设备或启动作业。默认前台入口仅监听 `127.0.0.1`。

服务使用 Python 标准库提供 HTTP，不需要 Node、npm、外网字体或 CDN。运行作业仍需要现有 NumPy、SciPy、OpenCV contrib、RealSense 和 pyAgxArm 依赖，可用 `bash scripts/check_environment.sh` 检查。

本工具针对可信局域网中的操作台，HTTP 不提供传输加密，也不提供用户账户隔离；不要直接暴露到公网。工程师 PIN 只用于限制临时使用未达标标定的操作，并非网络访问控制。

## 三个操作入口

| 入口 | 引导流程 |
| --- | --- |
| 首次安装 | 设备检查 → 人工示教并采样 → 浏览器画整板可见范围 → 生成路线 → HOME 后自动采样与求解 → 固定板登记 → 应用与桌面登记 |
| 重新标定 | 设备检查 → 生成路线 → HOME 后自动采样与求解 → 固定板登记 → 应用与桌面登记 |
| 相机位置变了 | 设备检查 → HOME 后观测固定板并恢复外参 → 应用与桌面登记 |

首次人工示教仍使用现场已有的手动移动方式。网页只读取反馈，点击“保存当前姿态”时检查停稳并采集；每次预览也会保留关节反馈，供后续生成示教路线。至少需要 12 组且具备两轴以上旋转多样性的有效姿态，建议 15–20 组。

画框使用原始采样图坐标，支持拖动和四个数值输入。只允许改写本 Web 会话生成的示教数据，不修改仓库内历史参考轨迹；修改范围后旧计划失效。画框是可见范围检查，不是环境碰撞检查，也不是排除其他板的检测 ROI。

“相机位置变了”只适用于基座、固定板、相机内参及身份保持不变的情况。恢复结果继承原手眼质量及残差，页面会注明这些残差不是恢复后独立精度验证。

固定板登记及相机恢复使用 `reference_board` 配置中的 `image_roi_xyxy` 识别固定桌面板。此区域与视频里的绿色手眼采样可见范围不同：固定板必须完整处于固定板识别区域内，且区域内不能出现另一块同型板。相机调整后需核对该区域是否仍覆盖固定板；角点不足时错误会列出实际数量、要求数量及识别区域，不会自动改用全画面或降低精度要求。

## 设备与停止行为

- 实时检查收到 3 秒内的相机画面和七轴反馈后，立即显示“设备已连接”。点击“完成检查并进入下一步”后，等待设备释放和静止证据，再进入下一步；不会自动启动采样。画面或反馈过期时不显示连接成功。
- 设备检查正常完成，且取得图像、七轴反馈和静止证据后，显示“设备已就绪”和“进入下一步”；失败或取消不显示就绪。检查期间不显示采样进度。
- 启动服务、浏览状态不连接设备。点击设备检查后才打开相机并读取机械臂反馈，不发送运动指令。
- 如发现 CONTROL/FAST、标定采集等进程占用，阻止开始并提示占用；PID 可在“操作记录与诊断”中查看。操作员须正常退出原程序后重新检测；工具不停止其他应用。
- 每次硬件作业同时持有 CAN 协作锁与原工作流锁。它们不能阻止不遵守锁的厂商网页或外部控制器；现场必须只保留一个控制来源。
- 一个作业只有启动页面可以发送采样、完成、停止和心跳。其他页面只能查看；刷新会创建新页面身份，旧作业将超时取消，不能直接接管续跑。
- 心跳默认 10 秒超时，请求受控停止并保留采样数据。页面关闭会尝试立即发送取消，失败时仍由超时机制处理。服务异常退出后，作业进程自身也检查心跳；继承的锁在作业退出前不会释放。
- 普通停止复用当前反馈关节的保持目标，并检查连续至少 0.5 秒、偏差不超过 0.1° 的新鲜反馈及运动状态。未取得证据时显示“未确认停止”，要求重新检查设备，不显示“已停止”。
- 网页停止不是硬件急停。通信异常、线程阻塞或设备清理超时会保持阻塞提示，不强行释放锁并启动新任务。出现实际异常运动应使用现场硬件急停。

视频由同一相机会话的独立读取线程发布，不把编码放入运动指令循环。过期画面和结束后的最后一帧都有明确标记。板端性能与受控停止仍须在现场验收，离线测试不能替代实机验证。

## 板识别与精度

手眼采样必须固定末端板并遮挡桌面同型板。启动和 HOME 姿态不要求标定板出现在画面中。Web 在到达采样姿态、停稳并完成识别后，保存每组样本前检查板检测结果是否与示教安装预测一致（40 mm / 15° 一致性上限，不是标定精度门槛）；采样时若机械臂明显改变而板几乎不动则拒绝保存。此检查不能证明所有姿态中的板身份，因此不能替代遮挡固定板和现场核对。

本项目在 `configs/calibration_workflow.json` 的 `quality_thresholds` 中配置求解门槛：`position_mm: 15`、`angle_deg: 5`，同时检查留出验证和全样本拟合。未配置该字段的旧工作流及底层命令默认仍为 5 mm / 2°。Web 页面和各步骤的门槛、超限标记及确认弹窗统一使用当前工作流门槛；包括历史示教参考与固定板登记内的源标定。

修改门槛后重启服务。Web 会用已有全样本及留出误差重新评估历史参考；证据缺失或无效时不会把原来的失败提升为达标。执行步骤时保存评估副本及原文件哈希，既有文件不被改写。已有路线使用副本时仍检查全部原始源文件哈希。误差数值与几何关系保持不变，结果不会自动应用。重新求解产生新结果时，旧固定板登记仍会失效。

生成路线与登记固定板是准备步骤，不弹出质量批准。自动采样、恢复相机位置、应用结果及重试桌面登记是关键步骤：使用当前门槛下未达标的结果时，需要管理员 PIN 解锁、确认误差并填写至少 5 字原因。解锁有效期 10 分钟；批准持久保存，绑定具体标定内容和门槛，同一结果在后续步骤及刷新后复用，不要求重新输入 PIN 或原因。结果、几何或门槛改变后重新判断；新的未达标结果需要新批准。批准不把未达标结果改为达标，Web 不继承 CLI 全局临时授权。

应用前备份原配置、手眼结果及桌面文件，然后调用原安装和桌面登记流程。桌面登记失败时保留运行限制，可点击“重试桌面登记”。回退文件保存在当前状态的 `backup` 目录；恢复前须停止使用设备的程序，并按原标定流程核对配置及桌面绑定。

## 配置与记录

设备、板尺寸、速度、HOME、板配置等仍读取 `configs/calibration_workflow.json`，修改后重启独立服务。Web 生成的状态优先于内置参考轨迹。新一次首次示教会使旧计划、旧登记及旧求解选择失效；生成新结果不会自动覆盖已安装结果。

默认运行目录为 `calibration/datasets/web/`（Git 忽略）：

| 路径 | 内容 |
| --- | --- |
| `state.json` | Web 当前数据集、路线、结果、登记、备份和桌面路径 |
| `datasets/` | 原始采样、逐帧示教、求解及安装备份 |
| `jobs/<作业ID>/` | 作业请求、配置快照、预览、进度、停止证据和日志 |
| `jobs/<作业ID>/capture_frames/attempt_NNNN/` | 每次手眼采样尝试的全部检测帧、标注图和数据，包括被拒绝的检测帧 |
| `audit.jsonl` | 开始、取消、完成、解锁事件及临时使用原因；不含明文 PIN |
| `quality-approvals.json` | 按结果和门槛保存的管理员批准及原因 |
| `engineer.json` | 加盐 PBKDF2 PIN 摘要，文件权限 0600 |
| `server.log` | 服务启动与异常日志 |

Web 人工示教和自动标定每次采样连续检测 3 帧，逐帧存为 `frame_NNN.png`（原图）、`frame_NNN_detected.png`（角点与坐标轴标注）和 `frame_NNN.json`（相机与板配置、时间、机械臂姿态、关节反馈、板位姿、重投影误差及检测状态）。检测失败也保存原图和带失败标识的图片，JSON 记录原因；不会将其当成有效检测。`capture.json` 列出该次采样尝试的帧和验证结果。这里只保存用于采样的检测帧，不保存运动视频、预览或采样前丢弃的缓存帧。

最终用于求解的样本仍保存为数据集内的 `sample_NNNN.png`、`sample_NNNN_detected.png` 和 `sample_NNNN.json`；新增 `frame_archive` 路径和 `selected_frame_index`（从 0 开始）可追溯选中了哪一帧。采样尝试通过不等于最终纳入求解，以数据集内的样本文件为准。固定板观测继续保存每帧的 `frame_NNN.png`、`frame_NNN_detected.png`，全部成功后的逐帧位姿与质量记录在 `observation.json` 的 `records` 中。升级前的历史数据只有当时保存的选中帧，不能恢复未保存的另外两帧。原 CLI 默认保存行为不变。

`--init-pin` 可用于部署时生成随机 8 位 PIN，明文仅存于受限目录的 `initial-pin.txt`（0600），不输出到日志。使用 `--set-pin` 修改后会删除该初始文件。不要提交运行目录或将它分享给其他人。

页面底部一直显示实际应用的配置路径。部署在独立 `dice_demo` 时，只更新该副本；即使同板上另有 `main/dice_demo` 正运行，也不会同步标定或自动重启它。

## 标定后的 HOME 回程

Web 自动采样成功求解后，自动按已有 HOME 逻辑回程，速度和加速度沿用工作流配置。开始自动标定前需同时确认 HOME 往返路径。只有新鲜七轴反馈确认 HOME 误差不超过 0.8°，且取得连续静止反馈，才显示本次操作完成。结果会先保存，回程失败或取消不会丢失结果，也不会自动重试。

Web 的每次 HOME（自动采样前后、相机恢复及单独回 HOME）在机械臂到位后，将右侧 Revo2 六路目标设为 `0 0 0 0 0 0`，发送 1 秒定时位置指令并等待指令时长，不读取或等待手指位置反馈。期间继续监测机械臂静止与 CAN 状态。发送失败、取消或机械臂移动仍会保留未完成标记。页面只说明“归零指令已发送”，不声称手指反馈已到位。作业 `hand_home.json` 记录 `verification=command_only`、`command_sent` 和目标值，`confirmed=false` 表示未验证手指位置。原命令行工具的 HOME 仍只控制机械臂。

“回 HOME”可单独执行回程，用于已有结果或失败后的人工重试；同样要求运动确认、设备独占和控制页心跳。运动控制就绪后才标记需要确认 HOME；启动检查失败不会直接标记为需要回程。作业清理或重新检查设备时，用新鲜静止反馈核对 HOME：最大关节偏差不超过 0.8° 且没有待发送的灵巧手归零指令时，清除待回程标记，无需重复运动；未取得证据时提示重新检查，确实偏离 HOME 时才提示回程。尚未确认 HOME 时，后端拒绝固定板登记、应用和桌面登记。首次手动示教、离线求解和原 CLI 流程不新增运动。

## 已保存的可见范围

视频预览默认叠加绿色可见范围框，按原始图像比例缩放并避开黑边；相机序列号、裁剪、内参或画面尺寸不匹配时不叠加。停止后保留的画面标为最后一帧。

可见范围直接显示在相机画面中，画面下方注明范围状态，不再单独展示静态采样图面板。已保存的范围数据和首次安装时的绘制、保存操作保持不变。

## 操作完成与结果显示

每步成功后在操作区显示完成提示，下一步按钮和步骤导航标绿，并写明下一步名称；重新执行使用次要按钮。失败、取消、设备状态未确认或输入已变化时，不沿用旧的完成提示。应用流程只有结果安装和桌面登记都成功才显示完成。

采样进度只在有明确样本总数的采样阶段显示。应用及桌面登记显示当前阶段，不沿用自动标定的 20 组目标；桌面登记预热后采集 5 帧 RGB-D 数据。

标定结果内的“每组标定误差”和“标定检测图片”默认收起，按需展开。误差表显示每组位置误差、角度误差及门槛判定，留出验证单独列出；矩阵和完整结果保留在详情中。新采样进行时，已有结果明确标记为上一次结果。

展开结果区“标定检测图片”可浏览当前数据集的历史采样。支持上一组/下一组、原图/检测标注图、逐帧选择、质量摘要和 PNG/JSON 下载。新版样本显示全部已存检测帧及被选中帧；历史样本只显示当时保存的最终图。采样结束自动刷新列表，进行中可手动刷新。浏览图片只读取已保存文件，不占用设备或获取作业控制权。
